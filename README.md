# mod_articlefooter

[English](README.en.md)

Модуль для Front-end частини сайту на Joomla 6, який виводить довільний HTML-блок в кінці матеріалів із вибраних категорій. Основний сценарій — **кнопка «Перейти до обговорення матеріалу»**, що веде на окрему тему форуму, створену для кожного матеріалу. Але модуль може вивести будь-який HTML, CSS чи JavaScript.

> **Важливо:** це не система коментарів. Модуль лише виводить HTML, який ви йому задали. Коментарі чи обговорення живуть в іншому місці (наприклад, на форумі phpBB).

## Можливості

- Показується лише на сторінці матеріалу (`com_content`, `view=article`).
- Працює лише в категоріях, які ви вибрали, за потреби разом з їхніми підкатегоріями.
- Дає змогу виключити цілі категорії (разом з усіма підкатегоріями) та окремі матеріали за ID.
- Виводить довільний HTML, CSS і JavaScript без фільтрації (не основний функціонал).
- Бере **окреме посилання для кожного матеріалу** з користувацького поля й підставляє його в HTML через плейсхолдер `{forum_url}`.
- Сам ховається, якщо поле порожнє, тож порожньої кнопки не буде, доки тема на форумі не створена.
- За бажанням пропускає HTML через плагіни контенту (`{loadmodule}`, `{emailcloak}` тощо).
- Побудований за архітектурою модулів Joomla 6: `AbstractModuleDispatcher`, фабрика хелперів, сервіс-провайдер і простори імен.
- Мовні файли: англійська (en-GB) та українська (uk-UA).

## Вимоги

- Joomla 6.x
- PHP 8.3 або новіший

## Встановлення

1. Запакуйте вміст папки модуля в архів `mod_articlefooter.zip` (файли `mod_articlefooter.xml`, `services/`, `src/`, `tmpl/` і `language/` мають лежати в корені архіву).
2. В адмінпанелі Joomla відкрийте **Система → Встановлення → Розширення** й завантажте архів.
3. Оновлення виконується так само: встановіть новий архів поверх старого. У маніфесті стоїть `method="upgrade"`, тому налаштування вже створених модулів зберігаються. Поля, додані в нових версіях, потрібно заповнити вручну.

## Налаштування

### 1. Створіть користувацьке поле для адреси теми

1. Перейдіть у **Матеріали → Поля → Створити**.
2. Виберіть тип **URL** (або **Текст**) і дайте йому назву, наприклад «Тема форуму».
3. Призначте його категоріям, у яких використовується модуль.
4. На вкладці **Параметри** встановіть **Автоматичний показ** у значення **Не показувати автоматично**. Інакше Joomla виведе значення поля прямо в тексті матеріалу. Модуль від цього параметра не залежить, бо читає значення безпосередньо з бази даних.

### 2. Створіть модуль

1. Перейдіть у **Матеріали → Модулі сайту → Створити** і виберіть **Підвал матеріалу (довільний HTML)**.
2. Заповніть налаштування:

| Параметр | Опис |
| --- | --- |
| Категорії | Модуль показується лише в матеріалах із цих категорій. |
| Враховувати підкатегорії | Якщо ввімкнено (за замовчуванням), вибір батьківської категорії охоплює й дочірні. |
| Виключені категорії | Матеріали з цих категорій та всіх їхніх підкатегорій ніколи не показують модуль, навіть якщо категорію вибрано вище. |
| Виключені матеріали (ID) | ID матеріалів через кому, де модуль ніколи не показується, наприклад `12, 57, 103`. |
| Поле з посиланням на тему форуму | Користувацьке поле матеріалу, значення якого підставляється замість `{forum_url}`. |
| HTML-код | HTML, який виводиться. За замовчуванням містить кнопку обговорення. |
| Обробляти плагінами контенту | Пропускає HTML через плагіни контенту. |

3. Виберіть **позицію шаблону**, яка виводиться після компонента. У Cassiopeia це `main-bottom`.
4. На вкладці **Призначення меню** виберіть **На всіх сторінках**. Модуль сам перевіряє категорію й показується лише на підходящих сторінках матеріалів. Це працює і для матеріалів, відкритих без пункту меню.
5. Опублікуйте модуль.

### 3. Щоденний процес

1. Опублікуйте матеріал.
2. Створіть тему на форумі.
3. Скопіюйте адресу теми (наприклад, `https://forum.example.com/viewtopic.php?t=123`).
4. Вставте її в користувацьке поле матеріалу й збережіть.

З цього моменту під матеріалом з'являється кнопка. Поки поле порожнє, нічого не виводиться.

## Де показується модуль

Модуль з'являється **лише на сторінці повного матеріалу** (`com_content`, `view=article`), під текстом статті.

Модуль **не виводиться** на головній сторінці, у виведенні «Обраних матеріалів», у списках і блогах категорій, у результатах пошуку та в інших місцях, де матеріали показані короткими анонсами, навіть якщо ці матеріали належать до вибраних категорій. Оскільки кнопка веде на обговорення конкретного матеріалу, її виведення має сенс лише на сторінці повної версії матеріалу. Виняток — головна сторінка, яка сама є одним матеріалом: там модуль показується, але за потреби можна прибрати в налаштуваннях.

Щоб виводити окремий блок під кожним елементом списку, потрібне перевизначення (override) шаблону цього списку, і цей модуль такого не підтримує.

## Позиція модуля в шаблоні

Модулю потрібна **позиція шаблону, що виводиться після компонента**. У Cassiopeia така є: `main-bottom`. Для власного шаблону потрібно створити свою позицію наприклад `article-footer`.

1. У файлі `index.php` шаблону, одразу після компонента:

```php
<jdoc:include type="message" />
<jdoc:include type="component" />
<?php if ($this->countModules('article-footer')) : ?>
    <jdoc:include type="modules" name="article-footer" style="none" />
<?php endif; ?>
```

2. У файлі `templateDetails.xml` шаблону, всередині `<positions>`:

```xml
<position>article-footer</position>
```

3. Виберіть цю позицію в налаштуваннях модуля й встановіть призначення в меню **На всіх сторінках**.

Не обгортайте позицію в шаблоні в `<div>` з відступами. Joomla рахує призначені модулі, а не їхній вивід, тож така обгортка залишала б порожній проміжок під статтями, де модуль нічого не показує. Модуль сам виводить `<div class="mod-articlefooter">`, лише коли є що показати, тому відступи задавайте в CSS для цього класу:

```css
.mod-articlefooter {
    margin-top: 1.5rem;
}
```

## HTML за замовчуванням

```html
<a class="btn btn-primary" href="{forum_url}" target="_blank" rel="noopener">Перейти до обговорення матеріалу</a>
```

`btn btn-primary` — це класи Bootstrap, доступні в шаблоні Cassiopeia. В іншому шаблоні замініть їх на власні. Вивід обгортається в `<div class="mod-articlefooter">`, яким можна користуватися для стилізації.

## Плейсхолдери

| Плейсхолдер | На що замінюється |
| --- | --- |
| `{forum_url}` | Значення вибраного користувацького поля. Приймаються лише абсолютні посилання `http://` і `https://`, значення екранується. Якщо воно порожнє або некоректне, модуль нічого не виводить. |
| `{article_title}` | Заголовок матеріалу (з екрануванням HTML). |
| `{article_id}` | ID матеріалу. |

## Як модуль вирішує, чи показуватись

1. Це сторінка матеріалу `com_content`.
2. У модулі вибрано хоча б одну категорію.
3. ID матеріалу немає в списку виключених матеріалів.
4. Категорія матеріалу (або будь-яка з її батьківських) не входить до виключених категорій.
5. Категорія матеріалу входить до вибраних (а за ввімкнених підкатегорій — до вибраних входить одна з її батьківських).
6. Якщо в HTML є `{forum_url}`, то користувацьке поле містить коректне посилання.

Якщо будь-яка перевірка не пройдена, модуль нічого не виводить, і Joomla не рендерить його обгортку.

## Оновлення та сумісність

У маніфесті вказано update-сервер, тому Joomla може сповіщати про нові версії модуля (**Система → Оновлення → Розширення**) і показувати інформацію про сумісність перед оновленням ядра. Файл оновлень опубліковано на сайті автора:

```
https://www.magnumblog.space/mod_articlefooter-update.xml
```

Рядок `<targetplatform name="joomla" version="6.*"/>` у цьому файлі повідомляє, що модуль призначений для Joomla 6.x.

### Випуск нової версії (автоматично)

Релізи збирає GitHub Actions, див. `.github/workflows/release.yml`.

**Одноразове налаштування**

1. Покладіть `release.yml` у `.github/workflows/` репозиторію й запуште його.
2. Переконайтеся, що workflow має право створювати релізи: у репозиторії відкрийте **Settings → Actions → General → Workflow permissions** і виберіть **Read and write permissions**. Workflow і сам запитує `contents: write`, але політика організації чи репозиторію може це обмежити.
3. Якщо модуль лежить не в корені репозиторію, вкажіть його папку в `MODULE_DIR` на початку workflow.

**Кожен випуск**

1. Збільште `<version>` у `mod_articlefooter.xml` (наприклад, до `1.2.2`) і закомітьте.
2. Запуште коміт, потім створіть і запуште тег, що починається з `v` і дорівнює версії:

```
git tag v1.2.2
git push origin v1.2.2
```

3. Дочекайтеся завершення workflow **Release** на вкладці **Actions**. Він перевіряє, що тег дорівнює версії в маніфесті, валідує PHP і XML, збирає `mod_articlefooter.zip`, рахує контрольну суму SHA-256, генерує `mod_articlefooter-update.xml` і створює реліз на GitHub з обома файлами.
4. Завантажте `mod_articlefooter-update.xml` із файлів релізу й покладіть у корінь сайту, замінивши старий. Після цього сайти на Joomla бачитимуть нову версію.

Якщо workflow завершився помилкою про те, що тег не збігається з версією в маніфесті, видаліть тег, виправте версію й створіть тег знову:

```
git tag -d v1.2.2
git push origin :refs/tags/v1.2.2
```

Файл оновлень, створений workflow, завжди відповідає архіву з того самого запуску, тож не змішуйте його з файлами з інших збірок.

### Випуск вручну

1. Збільште `<version>` у `mod_articlefooter.xml`.
2. Зберіть архів `mod_articlefooter.zip` (маніфест має лежати в корені архіву).
3. Опублікуйте архів як реліз на GitHub з тегом `v<версія>` (наприклад, `v1.2.1`).
4. Порахуйте контрольну суму: `sha256sum mod_articlefooter.zip`.
5. У файлі `mod_articlefooter-update.xml` змініть `<version>`, `<downloadurl>` і `<sha256>`, потім завантажте файл у корінь сайту.

Контрольна сума має точно збігатися з архівом у релізі. Якщо ви перезбираєте архів, порахуйте її знову, інакше Joomla відмовиться оновлювати. Файл оновлень не входить в архів модуля й лише розміщується на сайті. Якщо переносите репозиторій, змініть адреси у файлі оновлень і адресу update-сервера в маніфесті.

## Усунення проблем

- **Нічого не показується.** Перевірте, що модуль опублікований, має позицію, яка виводиться на сторінці, і призначений на всі сторінки. Переконайтеся, що категорія матеріалу вибрана й не виключена.
- **В одному матеріалі немає кнопки.** Найімовірніше, користувацьке поле порожнє або не починається з `http://` чи `https://`.
- **Посилання виводиться в тексті матеріалу.** Встановіть для поля параметр **Автоматичний показ** у значення **Не показувати автоматично**.
- **Модуль з'являється над матеріалом.** Виберіть позицію, яка виводиться після компонента.

## Безпека

- HTML-поле зберігається без фільтрації, це потрібно для довільного HTML і JavaScript. Право редагувати модулі повинні мати лише довірені адміністратори.
- Адреса з користувацького поля перевіряється й екранується перед підстановкою.

## Кешування

У модуля навмисно немає налаштувань кешу. Кеш модулів Joomla не знає, який саме матеріал відкритий, і міг би показувати однакові посилання у різних матеріалах.
